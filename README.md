# SPEAR LLM agent with frame-aligned in-loop recording

Python controls SPEAR's `BP_SphereAgent` in Unreal Engine 5.5. A vision LLM (Claude) receives the
agent camera image, world position, heading, goal and recent positions, and returns JSON
`{"forward": -1..1, "turn": -1..1}`. Each command is held until the next asynchronous decision arrives.
The recorder saves **every controlled engine frame** of the episode (image + pose + the action in effect),
including frames where no new LLM decision was made. Setup/warm-up/cleanup frames are not part of the episode.

## Environment and installation

Tested on macOS with Unreal Engine 5.5 (editor launch mode), the official SPEAR `apartment_0000` scene and
`BP_SphereAgent` (the agent from SPEAR's `examples/control_simple_agent`), using the live Anthropic API.
The assignment mentions SPEAR's standard ground agent (e.g. OpenBot / navigation agent); this project uses
`BP_SphereAgent` because it is the ground agent available in the SPEAR build used here. It has not been tested on Windows.

1. Install Unreal Engine 5.5 and build SPEAR as described in
   https://github.com/spear-sim/spear/blob/main/docs/getting_started.md
2. Install the SPEAR Python client from the matching checkout (Python 3.11):
   `pip install -e /path/to/spear/python`
3. Install this project's requirements: `python -m pip install -r requirements.txt`
4. `cp .env.example .env` and set `ANTHROPIC_API_KEY`. Never commit `.env` or a real key.
   The default model is `claude-opus-4-8`; set `LLM_MODEL` to override it. The Anthropic client uses a
   30-second timeout and at most one retry. If a call fails, the last command is kept and the error is logged;
   no scripted fallback policy is ever used. A run with zero applied LLM decisions fails validation.
5. `cp user_config.yaml.example user_config.yaml` and set the paths to your Unreal executable and the
   SpearSim `.uproject`. The runner supports launching the editor (it presses Play itself) or a game build,
   and closes the instance it launched. Quit any previously running Unreal app first (Cmd+Q).

## Run

```bash
python -u run_episode.py --frames 450 --llm-every 15 --preview
```

- A unique episode folder name is generated by default and an existing folder is never overwritten.
  Use `--episode <name>` to choose a name (an existing name is an error).
- Paths for `.env`, the default config and `recordings/` are relative to the script, not the terminal directory.
- `--preview` opens a window with the agent camera and an overlay (saved-frame count, real UE frame number, action).
  The overlay appears only in the live preview; saved PNGs and LLM observations are clean.
- `--frame-delay 0.1` slows wall-clock time between frames (useful for a screen-capture demo).
  Measured simulation time stays fixed at 30 fps.

The sample bundle and demo in this repository were produced with this runner
(`--frames 450 --llm-every 15 --episode demo_001`, the demo with `--frame-delay 0.1 --preview`).

## Part A: policy, goal and termination

Default goal: explore toward a distinctive visible object while avoiding walls and obstacles
(`--goal` or `EPISODE_GOAL` overrides it). A short history of positions and actions is given to the LLM so it can
notice when it is blocked; obstacle handling is decided by the LLM, not by a hand-coded motion policy.
Termination is a fixed frame budget: 450 frames by default (15 s of simulation at 30 fps).
This is an exploration episode; target-reaching success is not automatically evaluated or certified.

A request is attempted every `--llm-every` frames, provided the previous request has finished and its response
has been consumed. The frame loop never waits for the LLM. A returned action starts on the next recorded frame.
Responses that arrive after the final frame are not used or counted as applied decisions.

## Part B: stepping, timestamps and alignment

Each iteration applies the current action in `begin_frame()` and copies the camera buffer and poses in the matching
`end_frame(single_step=True)` block. The single-step boundary holds the engine at the start of the next frame while
Python writes files and services the preview. The image array is copied before leaving the frame block, because the
shared buffer is reused.

`UKismetSystemLibrary.GetFrameCount()` is sampled before the action and again with the observation; the two must match,
and consecutive recorded engine frame numbers must differ by exactly one. `UGameplayStatics.GetTimeSeconds()` provides
the measured game time. `t` is that time minus the first recorded frame's time (not an invented `frame_idx/30`).
Recording and validation both require every time increment to be within 0.001 s of 1/30. The fixed engine delta time
is explicitly set to 1/30.

Each row is the observation **after** that row's action. `location` is the sphere's world center and `rotation` is the
navigation root's heading as pitch/yaw/roll in degrees (not the tumbling physics rotation of the sphere). The camera pose
is stored separately. Distances are Unreal centimeters. The camera is 512x512. Native uint8 BGR is preserved; floating-point
BGR is clipped to [0,1] and scaled to uint8 for PNG and for the LLM (a display conversion, not lossless HDR storage).

## Output format

```
recordings/<episode>/
  frames/0.png ... 449.png
  manifest.jsonl
  decisions.jsonl
  llm_events.jsonl
  run_info.json
  resolved_config.yaml
  validation.json
  preview.jpg
```

Required manifest fields: `frame_idx`, `t`, `action`, `location`, `rotation`, `image`, `action_id`.
Extra fields: measured `engine_frame` and `sim_time`, camera pose, PNG hash and shape. `action_id=0` is the initial neutral command.
`decisions.jsonl` stores, per applied decision, the observation frame and image hash, response ID, model, returned JSON,
prompt text, latency and the first frame that used the action. `llm_events.jsonl` records submissions and consumed failures.

## Verification

The runner validates the saved bundle automatically and prints `RECORDING PASS` or `RECORDING FAIL`.
To re-check the committed sample:

```bash
python validate.py recordings/demo_001
python validate.py recordings/demo_001 demo/demo.mp4
```

Checks: at least 300 contiguous records, exact engine-frame increments, measured engine-time increments, decodable
images with matching counts and hashes, held-action consistency, and agreement between `decisions.jsonl` and the frames
where actions change. With a demo argument the video must also be readable and 30-90 s long. Warnings flag very dark or
identical images and almost no movement. This is a local check, not the organizer's official evaluator.

## Demo

`demo/demo.mp4` is a live screen capture of a run: the agent-camera preview with the saved-frame counter, the Unreal
window, and the terminal showing LLM decisions and recording progress. It demonstrates the run only; the Part B data
comes from the in-loop PNG/JSONL recorder, not from screen capture.

## Provenance and limits

Control and component setup is adapted from SPEAR's MIT-licensed `examples/control_simple_agent/run.py` and
`examples/control_editor/run.py` (see `SPEAR_LICENSE.txt`). Whether `BP_SphereAgent` / `apartment_0000` match the
organizer's intended agent and scene should be confirmed by the reviewer. Cross-run determinism of LLM outputs and
physics is not claimed, and navigation quality should be judged from the trajectory, frames and demo.
